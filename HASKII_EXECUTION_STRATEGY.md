## PART 2: POINTS ECONOMY DESIGN

### The Core Problem & Solution

**Challenge:** Points must feel valuable AND stay stable (no inflation)

**Current State:**
- Points earned through multiple activities
- Value set at ₦0.10 per point
- High supply → potential inflation risk

### Inflation Control Mechanisms

#### **1. Velocity Control (How fast points move)**

```
EARN RATES (monthly):
- Daily check-in: 50 pts × 30 days = 1,500 pts
- Daily missions: avg 200 pts × 25 days = 5,000 pts
- Video ads: 50 pts × 10/day × 30 = 15,000 pts
- Referrals: 500 pts × 1/month avg = 500 pts
- TOTAL EARN: ~22,000 points/month = ₦2,200 value perception

BURN RATES (redemption):
- Cosmetics: 100-500 pts
- Airtime: 900-4,500 pts
- Gift cards: 2,000-10,000 pts
- Point market sales: 5,000-20,000 pts
- Premium subscription: 10,000 pts (option to pay in points)

TARGET VELOCITY: 60-70% of earned points redeemed within 30 days
- Ensures healthy circulation
- Prevents hoard mentality
- Maintains value perception
```

#### **2. Supply Control (Emission rate management)**

```
DYNAMIC EARNING ALGORITHM:
Base reward × (System Health Score)

System Health Score = (Total Redeemable Points / Target Points Supply)

Example:
- Target supply: 500M points for 10K users
- Current supply: 220M points
- Score: 220M / 500M = 0.44 (44%)
- User earning rate: Normal × 0.44 = 44% base rate

When supply drops to 200M:
- Score = 200M / 500M = 0.40
- Earning rate: 40% (platform earning is too high)

This creates negative feedback loop:
- High redemptions → low supply → higher earning rates → more engagement
- Low redemptions → high supply → lower earning rates → less earning urgency
- System self-balances

Implementation: Add `system_health_score` to feature_limits table
```

#### **3. Value Preservation Through Tier-Locking**

```
TIER 1 (Free): ₦0.10 per point
- Can earn: up to 50K pts/month
- Can redeem: only to airtime/data/gift cards
- Point trading: 10% tax (100 pts costs 110 to buyer)

TIER 2 (Premium): ₦0.10 per point
- Can earn: unlimited (2x multiplier)
- Can redeem: all categories + marketplace
- Point trading: 2% tax (premium users pay less)
- Exclusive: Cash redemption (no middleman)

TIER 3 (Elite): ₦0.12 per point
- Can earn: unlimited (3x multiplier)
- Direct cash redemption at ₦0.12/point
- Marketplace arbitrage opportunity protected

This creates:
- Perceived value increase through tiers
- Revenue from tier upgrades
- Protection against gaming (free users pay more to trade)
- Incentive for premium conversion (lower trading costs)
```

#### **4. Price Discovery Through Market Mechanisms**

```
POINT MARKET (existing point_sell_orders table):
- Users set own prices for point trades
- Creates natural price discovery
- HASKii doesn't manipulate (trust)

MONITORING METRICS:
- Average price per point (track weekly)
- Transaction volume (track weekly)
- Price volatility (target: < 5% weekly)

If price goes below ₦0.09:
- Problem: Users think points losing value
- Solution: Increase redemption rates or reduce earning

If price goes above ₦0.11:
- Problem: Arbitrage opportunity for whales
- Solution: Increase earning rates or add more redemptions

DATABASE TRACKING:
Add to campaigns table:
- avg_point_price_per_week
- point_price_volatility
- user_trading_volume
- trading_concentration (Gini coefficient - detect if few users hold all points)

Target: Price stays within ₦0.095-0.105 range (99% of time)
```

#### **5. Seasonal Supply Management**

```
ACADEMIC CALENDAR-BASED EARNING:

Semester 1 (August-November): Normal earning
- Students have time, high engagement
- Normal emission rates

Semester 2 (January-April): Exam period
- Reduced earning rates (students busy)
- Higher point value (scarcity)
- 30% reduction in earning rates

Holidays (Dec, May-July): High earning
- Students have free time
- Festival redemptions (gift cards increase)
- 20% increase in earning rates

EXAMPLE IMPACT:
- Normal user: 1,500 check-in pts/month
- Exam period: 1,050 check-in pts/month (but worth more)
- Holiday: 1,800 check-in pts/month (spend more possible)

This creates:
- Natural engagement rhythm
- Anti-inflation mechanism
- Alignment with user behavior
- Predictability for vendors
```

### What NOT to Build

```

- Cost: ₦500K-1M development
- Why skip: Paystack/Flutterwave already work
- Alternative: Use existing APIs, build wrapper

❌ Mobile App (Native iOS/Android)
- Cost: ₦800K-1.5M development
- Why skip: React web app works on mobile
- Alternative: PWA (Progressive Web App) = web in app shell

❌ Dedicated Backend Services
- Cost: ₦300K+ per service
- Why skip: Supabase handles this
- Alternative: Supabase Edge Functions (serverless) = cheap

❌ Custom Analytics Platform
- Cost: ₦200K+ development
- Why skip: Supabase + Google Analytics is free
- Alternative: Build dashboards on top of existing data

❌ AI/ML Features (Recommendation, Fraud Detection)
```

## CRITICAL SUCCESS FACTORS

### 1. **Point Economy Stability**
- Must maintain ₦0.10 price within 5% range
- Supply growth must not exceed user growth by > 10%
- Recommend: Weekly monitoring + quarterly adjustments

### 2. **Network Effects**
- Referral coefficient must reach 1.2+ (each user brings 1+ new users)
- Merchant-to-user ratio healthy (1 merchant per 2,000 users)
- Without this, growth stalls

### 3. **User Trust**
- First cashout is psychological turning point
- Must deliver on promised point value
- Redemption processing < 48 hours
- Failure means churn spike

### 4. **Vendor Participation**
- First 10 merchants are hardest
- After 10, network effects help with sales
- Critical: Offer them real value (cost savings vs payment processors)

### 5. **Fraud Prevention**
- Phone verification required for high-value activities
- Referral fraud can drain ₦100K+ if unchecked
- Implement early, before scale

### 6. **Premium Conversion**
- 3-5% conversion rate = platform sustainable
- Below 3% = problem with premium value proposition
- Must continuously optimize premium features
